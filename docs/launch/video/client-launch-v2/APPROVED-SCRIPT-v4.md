# Approved 75-second launch script

Approved for production on 16 November 2026. This supersedes the historical `SCRIPT.md` and the v3 narration for the next three cuts.

Audience: Mac backend and full-stack developers who use database clients daily. The opening addresses TablePlus free-tier users who need more open tabs. The secondary invitation is for DBeaver users who want to try the same familiar workflow in TableIQ. This is a switching proposition, not a claim of universal superiority.

## Evidence and limits

- [TablePlus licensing](https://tableplus.com/docs/utilities/licensing): its free version limits simultaneous tabs to two. Its paid license is perpetual; do not describe this as a mandatory subscription.
- [DBeaver Community](https://dbeaver.io/about/) is already free and open source. That alone is not a differentiator against DBeaver.
- [TablePlus AI](https://tableplus.com/docs/llm-plugin) and [MCP](https://tableplus.com/docs/preferences/mcp) already exist. Do not call BYOK or MCP unique.
- [DBeaver discussion #40478](https://github.com/orgs/dbeaver/discussions/40478) reports slow tab/window interactions. It is anecdotal feedback, not a comparative benchmark of TableIQ.
- [Developer discussion about client selection](https://www.reddit.com/r/dataengineering/comments/1q04miu/fellow_des_whats_your_goto_database_client_these/) contains both friction and satisfied DBeaver users. Familiar navigation, schema exploration and query work matter alongside features.
- [Database-client launch discussion](https://news.ycombinator.com/item?id=50243653) raises switching costs around keyboard workflows, formatting, and trust in generated SQL. This supports showing an ordinary task and keeping execution explicit.

The available public feedback is qualitative and self-selected. No prevalence percentages, customer quotes, benchmark claims or invented beta endorsements are used. The founder reports 4–5 testers, but raw comments have not been supplied. Rust is a factual implementation detail, not evidence of being faster or lighter than another client.

## Capture acceptance

Only synthetic data. Actual input, actual Run, actual Rust database response. Development UI footage must be labelled; native stills must be labelled. No fabricated cursor, query, provider response, blocked-write event, competitor dialog or continuity between separate sessions. AI accuracy is supported by one previously verified native example, not a broad accuracy claim. Camera moves follow actual actions, settle for reading, and return to context.
