# Story routes considered

**Selected: One investigation, room to work.** A developer needs another query tab while investigating paid orders without a shipped shipment. A tab-limit hook leads into a real client workflow, optional AI, manual result verification and a short MCP extension. Light Pearl editorial scenes; real native app captures; one task carries the story. Recommended because an everyday database task establishes the category before AI terminology appears.

**Alternative: The answer, then the investigation.** Open on the two matching orders and work backwards through the SQL, schema and question. An object-to-object sequence carries the same two order IDs through the app. Stronger for a feature clip after people already know TableIQ; weaker for establishing the free client proposition.

**Alternative: Follow the agent’s query.** Open on an MCP run_query call, trace its SQL into the database client and inspect the result. Use one continuous visual path between the real agent and Activity. A useful separate developer-agent film; it would recreate the category confusion the founder asked us to fix if used as the main launch film.

The founder delegated the creative choice. The selected route is developed in SCRIPT.md, SPEC.md and the storyboard; no additional strategy approval was required to prepare these reviewable assets.
